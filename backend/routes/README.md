# Backend API Routes (Frontend Reference)

This folder is the single source of truth for **all HTTP routes** exposed by the backend.

- API base: `http://localhost:3000`
- API prefix: `/api/v1`
- Auth: `Authorization: Bearer <jwt>`

## Response envelope

All endpoints return a JSON envelope:

### Success

```json
{
  "success": true,
  "message": "...",
  "data": "(optional, present only when endpoint returns data)"
}
```

### Error

```json
{
  "success": false,
  "message": "..."
}
```

## Authentication (JWT)

Some routes are protected by the `AuthFilter`.

- Send header: `Authorization: Bearer <token>`
- If missing/invalid: `401` with `{ success: false, message: "Unauthorized: ..." }`

The backend embeds these JWT claims:
- `userId` (string)
- `role` (string)

## Pagination

### Users
- Query: `page` (default `1`), `limit` (default `10`)
- Constraint: `limit` must be `1..20` (else `400`)

### Notifications
- Query: `page` (default `1`), `limit` (default `10`), `type`
- `type` allowed: `HIGHLIGHTS` | `RECENT_UPDATES`

## Profile picture upload flow (pre-signed URL)

1) Call `POST /api/v1/users/uploadProfilePicture` with JSON `{ "file_extension": "png" }` and Bearer token.
2) Response contains `data.upload_url`.
3) Frontend uploads the file bytes to the `upload_url` using **HTTP PUT**.

Notes:
- The backend does not currently validate MIME type/content-type.
- The pre-signed URL is generated by AWS SDK and is time-limited.
